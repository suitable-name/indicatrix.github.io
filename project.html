1Workspace

Indicatrix is a Cargo workspace of libraries and applications, all MIT licensed. The libraries are published on crates.io, with their API documentation on docs.rs.

CrateKindDescriptionPublished
indicatrix library A physically-based spectral gemstone renderer that turns GemCAD-style cutting instructions into rendered output. crates.io · docs.rs
indicatrix-cut-core library Editor-core library for faceting cutting instructions: preform, tiers (including concave tiers and angle relations), undo/redo, and live solid validation. crates.io · docs.rs
indicatrix-solid library Pure-CPU solid rasterizer and 2D faceting diagram for a design's solid mesh, plus the pure replan planner. No GUI toolkit, no threads, no filesystem. Shared by the desktop editor and the web app. crates.io · docs.rs
indicatrix-editor library GUI-free faceting-design editor logic shared by the desktop editor and the web app: the editor session (design, undo/redo, selection, dirty tracking), tier, preform and material form parsing, plain-struct view models, the cutting sheet, Retarget, the guided walkthrough and tutorials, cutting mode, the angle sweep, the overall verdict and the solve policy. No GUI toolkit, no threads, no clock, no filesystem. crates.io · docs.rs
indicatrix-formats library Readers and writers for gemstone faceting design file formats. crates.io · docs.rs
indicatrix-vault library SQLite-backed storage, data models, and local import/export for gemstone faceting design libraries. crates.io · docs.rs
indicatrix-net library Wire protocol for offloading indicatrix spectral ray samples to a remote render worker: scene-state and radiance-buffer codecs, message framing, a build-compatibility handshake, and the TLS helpers and enrollment client shared by the viewer and the worker. It runs no server and opens no listening sockets. crates.io · docs.rs
indicatrix-dispatch library Sample-range scheduling for render lanes: a shared disjoint sample cursor, per-lane rate models, a lane pool that merges chunk sums deterministically, and a whole-item batch queue. No networking and no GUI types. crates.io · docs.rs
indicatrix-render-jobs library Render jobs: the frozen job file (scene, material, lighting, camera and export settings) shared by the desktop render queue and the command-line renderer, the job state machine, queue ordering, and the shell and PowerShell script writer. crates.io · docs.rs
indicatrix-cut app (desktop) Desktop faceting-design editor: library browsing, spectral 3D rendering, material retargeting, and a solid inspection view. crates.io · docs.rs
indicatrix-worker app (CLI / server) The coordinator (serve): serves an indicatrix-backed design catalogue over mutual TLS and accepts joining render workers. The optional worker feature adds render capacity — serve --render, join to work for a coordinator, and render, a one-shot scene-to-PNG CLI. crates.io · docs.rs
indicatrix-cli app (CLI) Headless command-line tool for faceting designs: info, solve, metrics, validate, optimize, retarget, sweep and export, from scripts, with no window and no GPU. Reads .indicatrix, .asc, .gem and .gcs and uses the same solver, retarget gate and optimizer as the desktop editor. Its render and tilt-video commands run saved render job files. crates.io · docs.rs
indicatrix-web app (browser) Browser build of indicatrix, served as static files: open or start a design (.indicatrix, .asc, .gem, .gcs), edit it in the same faceting CAD engine, and look at it as a solid, a faceting diagram and a spectral render traced on your CPU cores in Web Workers, with the brilliance, fire, windowing and extinction figures and the tilt curve. Files are read and saved as browser downloads; the design lives in the tab's session only. No design library, no remote rendering, no Deep Solve, no GPU renderer, no database. See the web app page. crates.io · docs.rs
indicatrix-web-core library The compute side of the browser build with no DOM and no GUI in it: the Web Worker protocol, the scene spec that builds the desktop's exact render scene, the CPU chunk tracer and its bit-exact accumulation, the worker-side solve, Optimize, metrics and tilt sweeps. Tested natively. crates.io · docs.rs
indicatrix-web-compute app (Web Worker) The Web Worker entry point of the browser build: decodes a message, runs the indicatrix-web-core handler, posts the reply. crates.io · docs.rs

2Roadmap

PLANNED, NOT IMPLEMENTED

Everything in this section is a plan, not a feature. None of it exists in the current source tree, none of it has a release date, and the order below is not a promise of sequence. It is listed so that the direction of the project is visible. Features that have since landed, such as planning stones from a 3D scan of the rough and cutting concave facets, are described on the studio page and no longer appear here.

Planned featureWhat it will doBuilds on
Colour from a photograph of the rough Pick the render colour from a photo of the actual rough rather than from a catalogue preset: sample the stone's colour in the picture and derive an absorption spectrum that reproduces it, so the preview shows the stone you have, not a generic one. (The Rough planner already locates inclusions from photos on a fixed camera rig; this is about the colour of the stone itself.) The spectral material model and the shared material catalogue (materials page), and the custom colour editor.
Optical-effect overlays in the render Highlight directly in the rendered image where windowing, extinction, brilliance and fire occur. Each effect can be shown as a coloured overlay on the stone, so a cutter sees at a glance which facets leak light straight through or go dark at the current viewing angle, instead of reading it only from a score or the tilt curve. (Today the Solid view already hatches pavilion facets at risk of windowing; the render itself has no overlay.) The optical metrics and the tilt performance sweep (studio page), which already measure these effects from the camera's point of view but report them only as numbers and curves.
Mobile app A phone or tablet client for browsing the library and viewing designs in high-definition renders. The rendering itself happens on a coordinator or worker over the existing remote protocol, so a mobile device gets the same quality as the desktop without tracing anything locally. Distributed rendering and the coordinator model (distributed page).
GPU rendering in the browser Let the web app trace on the GPU when the browser and graphics driver can take it, falling back to the CPU workers otherwise. Today the desktop's GPU kernel does not compile in browsers, so this needs a smaller, browser-sized kernel; it is being researched and is not promised. The GPU compute path and its equivalence harness (physics page), and the browser build's CPU worker pool (web app page).
Multi-language support The desktop studio and the web app in more languages than English: menus, dialogs, messages and the guided walkthrough, with a language picker, plus the printed cutting instructions and faceting diagram labels in the chosen language. The Slint interface toolkit's built-in translation support, which both applications already use; today every text in them is English only and none of it is marked for translation yet.
More database adapters Keep the design library in the database you already run: MySQL, PostgreSQL or another server, alongside the built-in SQLite file, so a workshop or club can share one library. The library storage in indicatrix-vault, which today writes a local SQLite database.

3Status and limitations

  • The faceting CAD (indicatrix-cut-core and the editor UI in apps/indicatrix-cut) is beta; its interaction model is still changing, so check a design against an established CAD before you cut it.
  • indicatrix-web is the browser build (live.indicatrix-suite.com, described on the web app page). It renders on the CPU in Web Workers (slower than the desktop's GPU path, so a few hundred samples take a while on a laptop), edits and solves designs with the same engine as the desktop, and keeps a design only for the life of the browser tab, so save your work as downloads. It has no design library, remote rendering, Deep Solve or GPU renderer, and it has no tutorials, cutting mode, history and variants, concave tools or command palette — see the web app page and its own README.md for the limits.
  • The GPU compute path requires a wgpu-supported adapter with at least 11 storage buffers per shader stage (MEGAKERNEL_STORAGE_BUFFERS, crates/indicatrix/src/renderer/gpu/context.rs); without one, rendering falls back to the CPU tracer. A concave stone, and a scene lit by one of the two UV lamp presets (physical-colour builds only), is always traced on the CPU, locally and on a remote worker, and renders slower than the same design without its tools.
  • Concave tiers have limits. Each tool placement is taken from the flat stone's measured width, the optimizer and the angle sweep score the flat stone, and the GPU does not trace tools. Clicking a groove or dimple selects its concave tier, Compare draws, traces and measures the stone with its tools, and the Rough planner places a concave design on its carved outline.
  • The Rough planner reads rough meshes as OBJ, STL (ASCII or binary) or PLY (ASCII or binary), up to 64 MiB, in a unit you choose (it suggests one when the size looks wrong but never applies it). Small scan defects are repaired on import: hair-wide gaps, faces turned the wrong way and holes up to 5 % of the bounding-box diagonal. A smooth scan is planned from the scan itself, with a simplified outline of at most 64 planes only for the grid, and every stone is still checked against the real scan; a scan plan stops at a time limit (120 s by default, shown as “Stopped at the time limit”) and shows the best layouts found. A mesh with more than 200,000 triangles, an open scan with bigger holes, or a mesh that crosses itself falls back to its convex outline with a note, except a smooth scan, which is refused (decimate it first). Inclusions can be added as closed meshes (or located from photos on a fixed camera rig); stones keep clear of them with a margin, while the weight and the yield count them as material. An inclusion that reaches the surface is refused, and inclusions on a block, cylinder or pebble rough are not available yet.
  • indicatrix-cli takes one design file per command. Its retarget accepts only a result the validity gate marks valid, where the desktop dialog also lets an unchecked change through, and its .gcs export is experimental, as in the editor.
  • Render jobs run one at a time and never start by themselves. A job freezes the design, material, lighting, camera and export settings, but not the remote worker: its address and certificates are read from Settings when the job runs.
  • Indicatrix is not jewellery CAD, a general 3D renderer, or a grading or appraisal instrument.
